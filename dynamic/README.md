# robot_delivery

Реализация динамической модели многороботной доставки на графе-острове по
алгоритму «Алгоритм динамической модели — итоговая версия по шагам» (Шаги
0–6):

- **Шаг 0** (проверка достижимости) — `check_feasibility`
  (`robot_delivery/feasibility.py`): до первого раунда проверяет, что все
  точки погрузки/разгрузки грузов лежат в одной компоненте связности графа
  `G' = (V, E_ready ∪ E_blocked)`, и что в этой компоненте есть хотя бы один
  доставщик и хотя бы один строитель. Если нет — алгоритм не запускает ни
  одного раунда и явно возвращает причину невыполнимости.
- **Шаг 1** (формирование коалиций) — `form_coalitions`
  (`robot_delivery/scheduler.py`): для зафиксированного варианта «1
  доставщик — 1 строитель» коалиции пересобираются заново **на каждом
  раунде** жадным паросочетанием по минимальному расстоянию `dist(v_d, v_b)`
  на графе `G` (с учётом переправ, доступных к возведению, но без учёта
  постройки).
- `ROUTE-AND-COST`, `ESTIMATE-TASK-COST` — эвристическая оценка стоимости
  операции «коалиция доставляет груз» (`robot_delivery/costs.py`). Доставщик
  и строитель **не обязаны физически встречаться**: приоритет отдан
  обязанности строителя проложить маршрут для доставщика. Доставщик едет по
  своему маршруту (`deliverer_pos -> c_start -> c_finish`) независимо и
  самостоятельно; строитель идёт от своей текущей позиции и строит все
  непостроенные мосты этого маршрута по очереди (а если для того, чтобы до
  них физически добраться, ему нужно построить что-то ещё — это тоже его
  обязанность). У каждого моста доставщик ждёт ровно до момента, когда
  строитель его достроит, если тот ещё не успел — иначе едет без задержки.
- **Шаги 2–6** (`SELECT-ROUND`, `RUN-DYNAMIC-ROUNDS`,
  `robot_delivery/scheduler.py`) — динамическое распределение грузов по
  раундам с глобально доступными построенными мостами. Способ распределения
  ВНУТРИ раунда сменный: `greedy` (глобальный жадный проход по
  отсортированной таблице приоритетов) или `round_robin` (коалиции выбирают
  груз по очереди, каждая — лучший для себя из ещё доступных). Если
  нескольким коалициям раунда нужен один и тот же ещё не построенный мост —
  какая из них его реально строит, решается **случайно** (Шаг 4, п.2);
  воспроизводимость обеспечивается параметром `rng_seed`. Позиция строителя
  после раунда обновляется только если он сам что-то построил (Шаг 5) —
  иначе остаётся прежней.
- `COMPUTE-DYNAMIC-COST-BRACKET` — диагностическая вилка «оценка vs факт»:
  `real`, `estimated_raw`, `estimated_pool`, `estimated_precollision`,
  `estimated_prognosis` и метрики разрыва `gap_raw` / `gap_pool` /
  `gap_precollision` / `gap_prognosis` (`robot_delivery/diagnostics.py`).
  `estimated_prognosis` — прогноз прямой эвристики (p = W_T, «чем дороже
  доставка — тем первее её нужно выполнить»), пересчитываемый на каждом
  раунде для каждой коалиции: мосты, уже построенные на предыдущих раундах,
  считаются бесплатными (по цене проезда), а мосты, которые ещё необходимо
  построить для маршрута, учитываются по полной стоимости (постройка +
  проезд) — то есть ровно так же, как строится сама таблица приоритетов на
  Шаге 2 (совпадает с `estimated_precollision`, см. ниже).
- Набор сменных эвристик приоритета `p` из «Постановки задачи» —
  стоимостные (1.1–1.4), геометрические/дистанционные (2.1–2.4) и выпуклая
  комбинация Greedy-Nearest/LPT (`robot_delivery/heuristics.py`).
- Генератор случайных сценариев (`robot_delivery/scenario.py`) и раннер
  экспериментов с графиками (`robot_delivery/experiment.py`,
  `robot_delivery/plotting.py`, `robot_delivery/cli.py`).

## Установка

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Нужен Python ≥ 3.9. Внешние зависимости — только `matplotlib` (для графиков);
всё остальное (граф, Dijkstra, планировщик) реализовано на чистом Python.

## Список доступных эвристик

```bash
python3 -m robot_delivery.cli --list-heuristics
```

| Ключ | Формула | Источник в «Постановке задачи» |
|---|---|---|
| `cost_direct` | p = W_T | 1.2, базовый вариант из фиксации задачи |
| `cost_inverse` | p = 1 / W_T | 1.1 |
| `cost_normalized` | p = W_T / Σ W_T (в таблице раунда) | 1.3 |
| `cost_by_agent_type` | p = W_b / W_d | 1.4 |
| `dist_min_deliverer` | p = 1 / dist(доставщик, груз) | 2.1 |
| `dist_max_deliverer` | p = dist(доставщик, груз) | 2.2 ("сначала сложное") |
| `dist_min_builder` | p = 1 / dist(строитель, груз) | 2.3 |
| `dist_combined` | p = 1 / (dist_доставщика + dist_строителя) | 2.4 |
| `convex_cost_load_{θ}` | θ·(близость по стоимости) + (1−θ)·(незагруженность пары) | раздел "Формирование расписания" (Greedy-Nearest/LPT) |
| `random_priority` | p ~ U(0,1), не зависит от стоимости | baseline для оценки качества остальных эвристик (см. `experiments/compare_direct_vs_random.py`) |

Можно добавить свою эвристику — см. `robot_delivery/heuristics.py`, реестр
`HEURISTICS`, интерфейс `Heuristic(per_cell=..., aggregate=...)`.

## Прогон экспериментов

```bash
python3 -m robot_delivery.cli \
    --heuristics cost_direct cost_inverse dist_min_deliverer dist_combined convex_cost_load_0.5 \
    --n-islands 20 \
    --n-pairs 3 \
    -n 20 \
    --n-runs 10 \
    --seed 42 \
    --trace \
    --output-dir outputs
```

### Основные параметры эксперимента

| Флаг | Смысл |
|---|---|
| `--n-islands` | Количество островов среды (вершин графа G) |
| `--n-pairs` | Количество пар роботов (коалиция 1 доставщик + 1 строитель) |
| `-n` / `--n-cargos` | Количество грузов n — **верхняя граница развёртки** |
| `--n-runs` | Количество прогонов (рандомайзер) на один сценарий |
| `--heuristics` | Какие эвристики приоритета `p` сравнивать |
| `--assignment-algos` | Какие алгоритмы распределения грузов внутри раунда сравнивать: `greedy` (по умолчанию) и/или `round_robin` |

**Как устроен цикл.** Число грузов не задаётся одним значением, а пробегает
диапазон **от `--n-pairs` до `-n` включительно**. Например, при `--n-pairs 3
-n 20` эксперимент прогоняется для 3, 4, 5, …, 20 грузов — 18 точек развёртки.
Нижняя граница выбрана как число пар роботов: при меньшем числе грузов часть
пар заведомо остаётся без назначения уже в первом раунде и сценарий
вырождается.

На **каждое** значение числа грузов генерируется `--n-runs` независимых
случайных инстансов (рандомайзер), и на каждом из них прогоняются **все**
сравниваемые комбинации (эвристика приоритета × алгоритм распределения) —
на одних и тех же сценариях, что делает сравнение честным. Итоговое число
прогонов модели:

```
|эвристик| × |алгоритмов распределения| × (n − n_pairs + 1) × n_runs
```

CLI печатает это число перед стартом и отчитывается о прогрессе по каждой
точке развёртки.

### Сравнение алгоритмов распределения грузов (greedy vs round-robin)

По умолчанию раунд распределяется жадно (`greedy`): вся таблица «пара x
груз» сортируется по приоритету один раз, и самая приоритетная в целом
ячейка получает назначение первой — при высокой конкуренции за грузы одна
пара может систематически "перехватывать" лучшие варианты. Альтернатива —
`round_robin`: пары получают ход по очереди (с сдвигом очереди по раундам,
чтобы не давать преимущество одной и той же паре), и на своём ходу пара
выбирает лучший для себя ещё доступный груз.

```bash
python3 -m robot_delivery.cli \
    --heuristics cost_direct \
    --assignment-algos greedy round_robin \
    --n-islands 20 --n-pairs 3 -n 20 --n-runs 10 --seed 42 \
    --output-dir outputs
```

Если задано больше одного `--assignment-algos` (и/или больше одной
`--heuristics`), все стандартные графики (`real_vs_estimated_bars.png`,
`gap_*_vs_ncargos.png`, `win_rate.png`) группируются по комбинации
"эвристика+алгоритм" (иначе результаты разных алгоритмов смешались бы под
одной меткой эвристики), и дополнительно строится
`assignment_comparison_real.png` — средняя фактическая стоимость доставки
(`real`) в зависимости от `n_cargos`, отдельная линия на каждую комбинацию,
на одном графике.

### Прочие параметры

- `--seed` — базовый seed; при одинаковом seed результат полностью воспроизводим.
- `--free-prob`, `--build-cost-factor` — параметры генератора графа (доля
  готовых переправ, стоимость постройки).
- `--trace` — дополнительно построить график накопления
  `real`/`estimated_raw`/`estimated_prognosis` по раундам для одного прогона
  (детальная трасса).
- `--output-dir` — куда сохранить `experiment_results.csv` и `.png`-графики.

### Что получится в `--output-dir`

- `experiment_results.csv` — сырые данные по каждому прогону (эвристика,
  `assignment` — алгоритм распределения грузов внутри раунда, seed,
  `run_index` — номер прогона рандомайзера, `n_islands`, `n_cargos`,
  `n_pairs`, real/estimated_raw/estimated_pool/estimated_precollision/
  estimated_prognosis, все четыре gap-метрики, idle, число раундов, флаги
  достижимости и полной доставки).
- `real_vs_estimated_bars.png` — средние `real` / `estimated_raw` /
  `estimated_pool` / `estimated_prognosis` по каждой эвристике (или
  комбинации, см. ниже).
- `gap_raw_vs_ncargos.png`, `gap_pool_vs_ncargos.png`,
  `gap_prognosis_vs_ncargos.png` — как разрыв (%) растёт с числом грузов,
  отдельная линия на эвристику (или комбинацию).
- `win_rate.png` — доля сценариев, где эвристика/комбинация дала минимальную
  реальную стоимость среди сравниваемых (только полностью доставленные
  сценарии).
- `assignment_comparison_real.png` (только если задано больше одного
  `--assignment-algos`) — средняя фактическая стоимость `real` в зависимости
  от `n_cargos`, отдельная линия на каждую комбинацию эвристика+алгоритм.
- `round_trace.png` (только если указан `--trace`) — накопительный
  real vs estimated_raw vs estimated_prognosis по раундам для одного прогона.

### Насколько прямая эвристика лучше случайного распределения?

`experiments/compare_direct_vs_random.py` — отдельный эксперимент, сравнивающий
`cost_direct` (p = W_T) с `random_priority` (p ~ U(0,1), т.е. случайное
распределение груза по парам) на одних и тех же сценариях (та же развёртка по
числу грузов, что и в cli.py):

```bash
python3 experiments/compare_direct_vs_random.py
```

Сохраняет в `outputs/direct_vs_random/`:

- `experiment_results.csv` — сырые данные обоих прогонов;
- `compare_real_vs_ncargos.png` — средняя реальная стоимость (`real`) обеих
  эвристик в зависимости от числа грузов на одном графике (прямое сравнение
  друг с другом);
- `compare_real_vs_estimated_bars.png` — для каждой эвристики реальная
  стоимость рядом с её же эвристической оценкой (сравнение с итоговой
  реальной стоимостью);
- `compare_win_rate.png` — доля сценариев, где каждая эвристика дала
  минимальную реальную стоимость.

На дефолтных параметрах (18 островов, 3 пары, грузов 3..24, 15 прогонов на
точку) `random_priority` в среднем даёт **более низкую** реальную стоимость,
чем `cost_direct` (~15% дешевле, выигрывает в ~93% сценариев) — т.е. сама по
себе стратегия "дорогие задачи первыми" не оптимизирует итоговую стоимость
доставки лучше случайного порядка на этой модели.

## Программное использование

Один сценарий:

```python
from robot_delivery.scenario import generate_scenario
from robot_delivery.experiment import run_single

scenario = generate_scenario(n_islands=18, n_cargos=12, n_pairs=3, seed=1)
result, bracket = run_single(scenario, "cost_direct")

print(result.feasible, result.all_delivered, result.n_rounds)
print(bracket.real, bracket.estimated_raw, bracket.estimated_pool)
print(bracket.gap_raw, bracket.gap_pool, bracket.gap_precollision)
```

Полная развёртка (то же, что делает CLI):

```python
from robot_delivery.experiment import cargo_sweep, run_suite

print(cargo_sweep(n_pairs=3, n_cargos_max=20))   # [3, 4, ..., 20]

rows = run_suite(
    heuristic_names=["cost_direct", "cost_inverse"],
    assignment_names=["greedy", "round_robin"],   # по умолчанию только ["greedy"]
    n_runs=10,          # прогонов рандомайзера на каждое значение числа грузов
    n_cargos_max=20,    # верхняя граница развёртки
    n_pairs=3,
    n_islands=20,
    base_seed=42,
)
print(len(rows))        # 2 x 2 x 18 x 10 = 720
```

## Известные допущения / упрощения реализации

- Шаг 0 проверяет достижимость только по связности графа (`E_ready ∪
  E_blocked`).
- Коалиции пересобираются заново на каждом раунде из ТЕКУЩИХ позиций всех
  доставщиков и строителей (жадное паросочетание по минимальному `dist`) —
  состав коалиции (кто с кем работает) между раундами может меняться. Эта
  пара по-прежнему формируется по геометрической близости, хотя физическая
  встреча внутри коалиции больше не требуется — минимальная `dist` остаётся
  разумным proxy для того, что близкий строитель, как правило, быстрее
  доберётся до мостов на маршруте доставщика.
- Случайный выбор коалиции, оплачивающей постройку моста при коллизии внутри
  раунда (Шаг 4, п.2), детерминирован параметром `rng_seed` в
  `run_dynamic_rounds`/`run_single` (по умолчанию берётся `seed` сценария) —
  прогон с одинаковыми `seed`/`rng_seed` полностью воспроизводим.
- Геометрические эвристики (2.1–2.4) используют дистанцию только по уже
  проходимым рёбрам (`FREE ∪ built`); если груз геометрически недостижим без
  постройки — используется реальная `W_d`/`W_b` из `ESTIMATE-TASK-COST` как
  запасное (fallback) значение расстояния.
- `estimated_precollision` считается через `W_T_initial` (полная оценка
  `ESTIMATE-TASK-COST` на момент построения таблицы раунда, ДО скидки за
  внутрираундовое резервирование мостов), а не через сырой ранг `p_rank` —
  потому что `p_rank` для дистанционных эвристик не находится в тех же
  единицах, что реальная стоимость, и несравним напрямую с `real`.
- `estimated_raw ≥ real` — гарантированное свойство модели, выполняется всегда
  (проверено тестом `test_estimated_raw_never_below_real`). `estimated_pool`,
  в отличие от `estimated_raw`, — лишь частичная коррекция (устраняет эффект
  переиспользования мостов, но не смену топологии маршрута из-за "забытой
  истории"), поэтому в единичных случаях может оказаться на доли процента
  ниже `real` — это соответствует описанию в самой постановке задачи
  ("устраняется только частично"), а не ошибка реализации.
- `estimated_prognosis` по построению равен `estimated_precollision` (оба —
  сумма `W_T_initial`): мосты, уже построенные на предыдущих раундах, бесплатны,
  а мосты, которые ещё нужно построить, учитываются по полной стоимости
  (постройка + проезд) — ровно так же, как считается сама таблица приоритетов
  на Шаге 2. Для дефолтных параметров генератора сценариев (`travel_cost_factor
  = 1.0`, то есть `w_E` длины ребра совпадает с длиной строящегося моста)
  `estimated_prognosis ≥ real`, как правило, выполняется — реальная стоимость
  может оказаться ниже только за счёт скидки при разрешении коллизий за мосты
  внутри раунда (Шаг 4). Строгой гарантии на все параметры генератора нет
  (аналогично `estimated_pool`), поэтому это не тестируется как жёсткий
  инвариант модели.
