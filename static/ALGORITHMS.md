# Алгоритмы решения задачи доставки гетерогенной группой роботов

Формализация четырёх основных алгоритмов (планирование маршрута, построение
приоритета, составление расписания, многокритериальная оптимизация) и двух
вспомогательных эвристик, реализованных в данной работе.

## Обозначения

| Символ | Смысл |
|---|---|
| $G = (V, E)$ | граф среды; $V$ — острова, $E = E_{free} \cup E_{blocked}$ — переправы |
| $w_E(e)$ | стоимость проезда по ребру $e$ |
| $w_{build}(e)$ | стоимость строительства ребра $e \in E_{blocked}$ |
| $w_V(v)$ | стоимость проезда через вершину $v$ |
| $\ell(e)$ | физическая длина ребра $e$ |
| $L$ | максимальная допустимая длина одного строящегося моста |
| $c_i$ | груз $i$, с точками $v_s^i$ (погрузка) и $v_f^i$ (разгрузка) |
| $U_i = (\delta_i, \beta_i)$ | коалиция: доставщик $\delta_i$ и строитель $\beta_i$, закреплённые за $c_i$ |
| $P^*$ | найденный маршрут доставки |
| $E_b \subseteq E_{blocked}$ | множество мостов, построенных в рамках маршрута $P^*$ |
| $W_d^i, W_b^i$ | стоимость операций доставчика / строителя для задачи $i$ |
| $\gamma$ | множитель удорожания строительства (`build_cost_multiplier`) |

## Постановка задачи: минимизация общей стоимости расписания

**Дано:** граф среды $G$, грузы $C = \{c_1, \dots, c_n\}$ ($n \gg m$), коалиции $\mathcal{U} = \{U_1, \dots, U_m\}$ (1 доставщик : 1 строитель), жадный алгоритм построения мостов (Эвристика A), дающий детерминированную стоимость $W_T(U_k, c_i \mid v_{\delta_k}, v_{\beta_k})$ обслуживания груза $c_i$ парой $U_k$, стоящей в данный момент в позиции $(v_{\delta_k}, v_{\beta_k})$.

**Переменные решения:**
1. назначение $\pi: C \to \mathcal{U}$ — какая пара обслуживает какой груз;
2. порядок $\sigma_k$ — перестановка очереди $C_k = \pi^{-1}(U_k)$ для каждой пары.

**Целевая функция:**

$$
\min_{\pi,\ \{\sigma_k\}} \ \Phi(\pi, \sigma) = \sum_{k=1}^{m} \sum_{j=1}^{|C_k|} W_T\Big(U_k,\ \sigma_k(j) \ \Big|\ v_{\delta_k}^{(j-1)}, v_{\beta_k}^{(j-1)}\Big)
$$

где позиция $\big(v_{\delta_k}^{(j-1)}, v_{\beta_k}^{(j-1)}\big)$ рекурсивно определяется как точка завершения $(j-1)$-й задачи в порядке $\sigma_k$ (или начальная позиция при $j=1$).

**Ограничения:** $\bigcup_k C_k = C$, $C_k \cap C_{k'} = \emptyset$ при $k \neq k'$; для каждой пары $(U_k, c_i)$ существует допустимый маршрут при заданном $L$.

Это обобщение задачи **параллельного машинного расписания с зависящими от последовательности временами обработки** (parallel machine scheduling with sequence-dependent processing times) — NP-трудная задача даже при фиксированном $\pi$. Полный перебор по $\pi$ и всем $\sigma_k$ неподъёмен при $n \gg m$, поэтому применяется **двухуровневая жадная декомпозиция**:

- **Алгоритм 0** (ниже) — эвристика для $\pi$, выполняется один раз, до начала расписания;
- **Алгоритм 1 + Алгоритм 2** — эвристика для $\sigma_k$ внутри каждой пары, динамический приоритет $p(c_i) = W_T^i$, пересчитываемый на каждом шаге (граф приоритетов — визуализация именно этого шага).

## Алгоритм 0. Назначение грузов парам (π)

**Вход:** грузы $C$, коалиции $\mathcal{U}$ в начальных позициях, граф $G$, ограничение $L$.
**Выход:** назначение $\pi: C \to \mathcal{U}$.

Рассмотрены два варианта, целящиеся в **разные** компоненты целевой функции.

### 0.1. LPT (Longest Processing Time first) — балансировка максимума

Классическая эвристика теории расписаний (Graham, 1969) для $P\,||\,C_{\max}$: грузы сортируются по убыванию оценённой стоимости $W_T^i$ и назначаются по принципу «самый дорогой груз — паре с наименьшей текущей загрузкой». Для $P\,||\,C_{\max}$ имеет доказанную гарантию приближения $\frac{4}{3}-\frac{1}{3m}$ от оптимума.

```
Algorithm 0.1  ASSIGN-LPT(C, 𝒰, G, L)
Input:  грузы C, коалиции 𝒰 (начальные позиции), граф G, ограничение L
Output: назначение π: C → 𝒰

1:  for each c_i ∈ C do
2:      W_T^i ← min_{U_k ∈ 𝒰} FIND-ROUTE-CHEAPEST-BRIDGE(G, c_i, U_k, L).cost
3:  end for
4:  sort C by W_T^i in descending order              ▷ LPT: длинные задания первыми
5:  load[U_k] ← 0  for all U_k ∈ 𝒰
6:  for each c_i ∈ C (в порядке убывания W_T^i) do
7:      U* ← arg min_{U_k ∈ 𝒰} load[U_k]              ▷ наименее загруженная пара
8:      π(c_i) ← U*
9:      load[U*] ← load[U*] + W_T(U*, c_i | начальная позиция U*)
10: end for
11: return π
```

**ВАЖНОЕ ОГРАНИЧЕНИЕ (установлено эмпирически).** Критерий Грэма доказан для минимизации **максимума** $\max_k \mathrm{load}(U_k)$ (makespan), а не **суммы** $\sum_k \mathrm{load}(U_k)$. Если стоимость $W_T^i$ не зависела бы от позиции исполнителя (как в классической постановке), сумма была бы **инвариантна** к любому назначению $\pi$ — это просто перегруппировка одного и того же набора слагаемых. В нашей задаче $W_T^i$ зависит от текущей позиции пары, поэтому сумма всё же меняется от $\pi$ — но эта зависимость никак не связана с тем, что оптимизирует LPT, и эмпирически LPT может **проигрывать** наивному round-robin по критерию $\Phi$ (сумма) на части сценариев, несмотря на лучшую балансировку нагрузки.

### 0.2. Greedy Nearest Assignment — прямая минимизация суммы

Каждый груз (в порядке поступления) назначается паре, для которой его обслуживание **обойдётся дешевле всего прямо сейчас**, с учётом уже сделанных назначений — позиция пары виртуально продвигается после каждого назначения, имитируя реальное исполнение:

```
Algorithm 0.2  ASSIGN-GREEDY-NEAREST(C, 𝒰, G, L)
Input:  грузы C, коалиции 𝒰 (начальные позиции), граф G, ограничение L
Output: назначение π: C → 𝒰

1:  v_δ[U_k], v_β[U_k] ← начальные позиции,  for all U_k ∈ 𝒰
2:  π ← ∅
3:  for each c_i ∈ C (в порядке поступления) do
4:      U* ← arg min_{U_k ∈ 𝒰} W_T(U_k, c_i | v_δ[U_k], v_β[U_k])
5:      π(c_i) ← U*
6:      (P*, E_b, _, _) ← FIND-ROUTE-CHEAPEST-BRIDGE(G, c_i, U*, L)
7:      v_δ[U*] ← v_f^{c_i}                          ▷ виртуальное продвижение позиции
8:      v_β[U*] ← последняя вершина E_b (или v_f^{c_i}, если E_b = ∅)
9:  end for
10: return π
```

Это «cheapest insertion»-эвристика, прямо целящаяся в минимизацию $\Phi$, а не в балансировку максимума.

### 0.3. Взвешенное назначение — управляемый компромисс между Φ и Cmax

Оба предыдущих варианта — частные случаи одной обобщённой эвристики с параметром $\lambda \in [0,1]$, нормирующим вклад двух критериев на каждом шаге назначения:

$$
U^*(\lambda) = \arg\min_{U_k} \Big[\, \lambda \cdot \hat{w}_T(U_k, c_i) \;+\; (1-\lambda) \cdot \widehat{\mathrm{load}}(U_k) \,\Big]
$$

где нормировка выполняется **относительно текущего шага** (минимум/максимум среди пар-кандидатов прямо сейчас), чтобы складывать величины разного масштаба:

$$
\hat{w}_T(U_k, c_i) = \frac{W_T(U_k, c_i) - w_{\min}}{w_{\max} - w_{\min}}, \qquad
\widehat{\mathrm{load}}(U_k) = \frac{\mathrm{load}(U_k) - l_{\min}}{l_{\max} - l_{\min}}
$$

```
Algorithm 0.3  ASSIGN-WEIGHTED(C, 𝒰, G, L, λ)
Input:  грузы C, коалиции 𝒰 (начальные позиции), граф G, ограничение L, λ ∈ [0,1]
Output: назначение π: C → 𝒰

1:  v_δ[U_k], v_β[U_k] ← начальные позиции,  load[U_k] ← 0,  for all U_k ∈ 𝒰
2:  π ← ∅
3:  for each c_i ∈ C (в порядке поступления) do
4:      W ← { W_T(U_k, c_i | v_δ[U_k], v_β[U_k]) : U_k ∈ 𝒰 }
5:      w_min, w_max ← min(W), max(W);  l_min, l_max ← min(load), max(load)
6:      for each U_k ∈ 𝒰 do
7:          ŵ_T(U_k) ← (W[U_k] - w_min) / (w_max - w_min + ε)
8:          load̂(U_k) ← (load[U_k] - l_min) / (l_max - l_min + ε)
9:          score(U_k) ← λ·ŵ_T(U_k) + (1-λ)·load̂(U_k)
10:     U* ← arg min_{U_k} score(U_k)
11:     π(c_i) ← U*;  load[U*] ← load[U*] + W[U*]
12:     обновить v_δ[U*], v_β[U*]                  ▷ виртуальное продвижение позиции
13: end for
14: return π
```

**Свойство:** $\lambda = 1$ даёт $\pi$, тождественное Greedy Nearest Assignment (0.2) — формула вырождается в $\arg\min_{U_k} \hat{w}_T(U_k, c_i)$, что после нормировки сохраняет тот же порядок, что и без неё. $\lambda = 0$ даёт жадную балансировку нагрузки — на каждом шаге выбирается пара с минимальной текущей загрузкой, без учёта стоимости конкретного груза (упрощённый аналог LPT, без предварительной сортировки грузов по убыванию).

**Построение Парето-фронта.** Перебор $\lambda$ по сетке $\{0, \frac{1}{N}, \dots, 1\}$ даёт множество точек $\big(\Phi(\lambda), C_{\max}(\lambda)\big)$; выделение недоминируемого подмножества выполняется идентично Алгоритму 4.2 (попарное сравнение по двум осям).

**Эмпирический результат** (`experiments/main_pareto_assignment.py`): зависимость $\Phi(\lambda)$ и $C_{\max}(\lambda)$ имеет **ступенчатую**, не гладкую форму (комбинаторная природа задачи назначения — решение скачком меняется на пороговых значениях $\lambda$). На усреднённых по 10 случайным сценариям данных Парето-фронт состоит из промежуточных значений $\lambda \approx 0.5$–$0.7$ — оба «крайних» режима ($\lambda=0$ и $\lambda=1$) оказываются **доминируемыми**: существуют промежуточные $\lambda$, дающие одновременно меньшую сумму и меньший максимум, чем оба чистых метода. Это означает, что ни LPT, ни Greedy Nearest по отдельности не являются Парето-оптимальным выбором — компромиссная эвристика превосходит оба «полюса».

**Сложность Алгоритма 0:** оба варианта — $O(n \cdot m \cdot C_A)$, где $C_A$ — стоимость одного вызова Эвристики A; для LPT добавляется $O(n\log n)$ на сортировку.

**Эмпирический результат** (15-точечная сетка по числу грузов, 5 случайных конфигураций на точку, см. `experiments/main_assignment_comparison.py`): Greedy Nearest Assignment даёт устойчивое улучшение $\Phi$ относительно round-robin на **всех** проверенных масштабах (от +2.8% до +9.4%), тогда как LPT даёт нестабильный результат, временами уступающий round-robin (до −1.9%). Это подтверждает теоретическое объяснение: LPT оптимизирует не ту целевую функцию, которая минимизируется в данной задаче.

## Алгоритм 1. Построение приоритета и графа приоритетов

**Вход:** груз $c_i$, граф среды $G$, коалиция $U_i = (\delta_i, \beta_i)$ с текущими позициями $v_{\delta_i}, v_{\beta_i}$.
**Выход:** скалярный приоритет $p(c_i) \in \mathbb{R}_+ \cup \{\infty\}$.

Приоритет строится как обратная величина «узкого места» (bottleneck) коалиции — максимума из расстояний по прямой от каждого агента до точки погрузки:

$$
p(c_i) = \dfrac{1}{\max\Big(\mathrm{dist}(v_{\delta_i},\, v_s^i),\ \ \mathrm{dist}(v_{\beta_i},\, v_s^i)\Big)}
$$

где $\mathrm{dist}(\cdot,\cdot)$ — евклидово расстояние между координатами вершин. Использование $\max$, а не среднего или суммы, отражает то, что коалиция готова к выполнению задачи только тогда, когда оба агента достигли точки погрузки — общая готовность ограничена самым медленным агентом.

```
Algorithm 1  COMPUTE-PRIORITY(c_i, G, δ_i, β_i)
Input:  груз c_i, граф среды G, коалиция (δ_i, β_i) с позициями v_δ, v_β
Output: приоритет p(c_i)

1:  d_δ ← EuclideanDistance(v_δ, v_s^i)
2:  d_β ← EuclideanDistance(v_β, v_s^i)
3:  bottleneck ← max(d_δ, d_β)
4:  if bottleneck = 0 then
5:      return +∞                       ▷ агент уже в точке погрузки
6:  end if
7:  return 1 / bottleneck
```

**Сложность:** $O(1)$ на один груз (две операции вычисления расстояния).

### 1.1. Построение графа приоритетов

Дискретизация непрерывной шкалы $p(c_i)$ в $k$ уровней («слева — высокий приоритет, справа — низкий») выполняется **квантильным разбиением**, устойчивым к выбросам:

```
Algorithm 1.1  BUILD-PRIORITY-GRAPH(C, k)
Input:  множество грузов C = {c_1, …, c_n}, число уровней k
Output: отображение level: C → {1, …, k}

1:  for each c_i ∈ C do
2:      p_i ← COMPUTE-PRIORITY(c_i, G, δ_i, β_i)
3:  end for
4:  sort C by p_i in descending order            ▷ индекс idx = 0 … n-1
5:  for idx ← 0 to n-1 do
6:      level(c_{(idx)}) ← min(k, ⌊idx · k / n⌋ + 1)
7:  end for
8:  return level
```

**Инвариант:** при $(n_i, n_j) \in E_T$ (родитель–потомок в дереве приоритетов) выполняется $p(n_j) < p(n_i)$ — монотонное убывание вдоль ветвей гарантируется самой процедурой сортировки и разбиения, без отдельной проверки.

**Сложность:** $O(n \log n)$ — доминирует сортировка.

## Алгоритм 2. Расписание выполнения по очереди приоритета

**Вход:** граф среды $G$, множество грузов $C$ с фиксированным назначением $\mathrm{assigned\_pair}(c_i)$, множество пар $\mathcal{U} = \{U_1, \dots, U_m\}$, параметр $L$.
**Выход:** расписание $T = \{T_1, \dots, T_n\}$, суммарные стоимости $W_d^{total}, W_b^{total}$, признак полноты доставки.

Назначение «груз → пара» задаётся **до** запуска алгоритма (не оптимизируется). Каждая пара обслуживает свою независимую очередь грузов; порядок внутри очереди определяется приоритетом (Алгоритм 1), пересчитываемым **динамически** перед каждым выбором — относительно текущей (уже сместившейся после предыдущих доставок) позиции пары.

```
Algorithm 2  SCHEDULE(G, C, 𝒰, L)
Input:  граф G, грузы C с assigned_pair(·), коалиции 𝒰, ограничение L
Output: расписание T, W_d^total, W_b^total, all_delivered

1:  for each U_k ∈ 𝒰 do
2:      Pending[U_k] ← { c_i ∈ C : assigned_pair(c_i) = U_k }
3:  end for
4:  T ← ∅;  W_d^total ← 0;  W_b^total ← 0;  t ← 0
5:  for each U_k ∈ 𝒰 do                              ▷ пары работают независимо
6:      t ← 0
7:      while Pending[U_k] ≠ ∅ do
8:          for each c_i ∈ Pending[U_k] do
9:              p_i ← COMPUTE-PRIORITY(c_i, G, U_k)    ▷ от ТЕКУЩЕЙ позиции U_k
10:         end for
11:         c* ← arg max_{c_i ∈ Pending[U_k]} p_i
12:         (P*, E_b, W_d, W_b) ← FIND-ROUTE(G, c*, U_k, L)     ▷ Алгоритм 3
13:         if P* не найден then
14:             return (T, W_d^total, W_b^total, FALSE)         ▷ L недопустимо
15:         end if
16:         v_δ(U_k) ← v_f^{c*}                        ▷ доставщик остаётся на месте доставки
17:         v_β(U_k) ← последняя вершина построенного моста (или v_f^{c*}, если мостов не было)
18:         T ← T ∪ { (c*, U_k, P*, E_b, W_d, W_b) }
19:         W_d^total ← W_d^total + W_d;  W_b^total ← W_b^total + W_b
20:         Pending[U_k] ← Pending[U_k] \ {c*}
21:     end while
22: end for
23: return (T, W_d^total, W_b^total, TRUE)
```

**Сложность:** $O\!\left(\sum_k n_k \cdot \big(n_k + C_{\text{route}}\big)\right)$, где $n_k = |\mathrm{Pending}[U_k]|$ — пересчёт приоритета линеен по оставшейся очереди на каждом шаге, $C_{\text{route}}$ — стоимость Алгоритма 3.

## Алгоритм 3. Поиск маршрута и минимального набора мостов

**Вход:** граф среды $G$, груз $c_i$, коалиция $U_i = (\delta_i, \beta_i)$, ограничение $L$, параметр $k_{alt}$ (число альтернативных путей).
**Выход:** маршрут $P^*$, множество построенных мостов $E_b$, раздельные стоимости $W_d, W_b$.

### 3.1. Проверка достижимости без строительства

Перед поиском с учётом $E_{blocked}$ проверяется, существует ли путь **только** через $E_{free}$ — если да, строительство не требуется вовсе, независимо от $L$ (свойство «мост избыточен, если граф уже связан»):

```
Algorithm 3.1  CHECK-FREE-PATH(G, v_s, v_f)
Input:  граф G, точки v_s, v_f
Output: путь P по подграфу G[E_free], либо ⊥

1:  G_free ← подграф G, содержащий только рёбра kind = free
2:  if v_s ∉ G_free or v_f ∉ G_free then
3:      return ⊥
4:  end if
5:  if not HasPath(G_free, v_s, v_f) then
6:      return ⊥
7:  end if
8:  return Dijkstra(G_free, v_s, v_f)
```

### 3.2. Построение приведённого графа

```
Algorithm 3.2  BUILD-WEIGHTED-GRAPH(G, L, γ)
Input:  граф G, ограничение L, множитель стоимости строительства γ
Output: приведённый граф G'

1:  G' ← (V, ∅)
2:  Comp ← ConnectedComponents(G[E_free])         ▷ для фильтра избыточности
3:  for each e = (u, v) ∈ E do
4:      if kind(e) = impossible then continue
5:      if kind(e) = blocked then
6:          if ℓ(e) > L then continue              ▷ физически невозможно построить
7:          if u, v лежат в одной компоненте Comp then continue   ▷ избыточный мост
8:          ŵ(e) ← γ · w_{build}(e) + w_E(e)
9:      else                                        ▷ kind(e) = free
10:         ŵ(e) ← w_E(e)
11:     end if
12:     add e to G' with weight ŵ(e)
13: end for
14: return G'
```

### 3.3. Выбор недоминируемого пути

Вместо единственного кратчайшего по $\hat w$ пути перебираются $k_{alt}$ кратчайших **простых** путей; для каждого раздельно вычисляются $W_d$ и $W_b$, и выбирается путь, не доминируемый другими по паре $(W_d, W_b)$, с минимальной суммой среди недоминируемых:

```
Algorithm 3.3  FIND-ROUTE(G, c_i, U_i, L, k_alt)
Input:  граф G, груз c_i, коалиция U_i, ограничение L, число альтернатив k_alt
Output: (P*, E_b, W_d, W_b) или ⊥ (недостижимо)

1:  P ← CHECK-FREE-PATH(G, v_s^i, v_f^i)
2:  if P ≠ ⊥ then
3:      return (P, ∅, PathCost_d(P), 0)             ▷ строительство не требуется
4:  end if
5:  G' ← BUILD-WEIGHTED-GRAPH(G, L, γ)
6:  if not HasPath(G', v_s^i, v_f^i) then
7:      return ⊥
8:  end if
9:  Π ← первые k_alt кратчайших простых путей G'[v_s^i → v_f^i] по ŵ
10: Scored ← ∅
11: for each π ∈ Π do
12:     (W_d^π, W_b^π, E_b^π) ← EVALUATE-PATH(G', π, U_i)
13:     Scored ← Scored ∪ {(π, W_d^π, W_b^π, E_b^π)}
14: end for
15: NonDom ← { s ∈ Scored : ∄ s' ∈ Scored, s' ≼ s, s' ≠ s }   ▷ Парето-недоминируемые
16: (P*, W_d, W_b, E_b) ← arg min_{s ∈ NonDom} (W_d^s + W_b^s)
17: return (P*, E_b, W_d, W_b)
```

где $s' \preceq s \iff W_d^{s'} \le W_d^{s} \wedge W_b^{s'} \le W_b^{s} \wedge s' \neq s$ — отношение доминирования по Парето.

### 3.4. Оценка стоимости одного пути

```
Algorithm 3.4  EVALUATE-PATH(G', π, U_i)
Input:  приведённый граф G', путь π, коалиция U_i = (δ_i, β_i)
Output: (W_d, W_b, E_b)

1:  E_b ← { (u,v) ∈ π : kind(u,v) = blocked }
2:  W_d ← Σ_{v ∈ π} w_V(v) + Σ_{(u,v) ∈ π} w_E(u,v)            ▷ стоимость доставчика
3:  E_b^{sorted} ← мосты E_b, упорядоченные по позиции вдоль π
4:  cur ← v_{β_i};  W_b ← 0
5:  for each (u, v) ∈ E_b^{sorted} do
6:      π_sub ← Dijkstra(G', cur, u)                  ▷ строитель добирается до моста
7:      if π_sub не существует then return (∞, ∞, ∅)
8:      W_b ← W_b + PathCost_d(π_sub) + w_{build}(u,v) + w_E(u,v) + w_V(v)
9:      cur ← v
10: end for
11: return (W_d, W_b, E_b)
```

**Сложность Алгоритма 3:** доминирует перечисление $k_{alt}$ простых путей через `shortest_simple_paths` — $O\!\big(k_{alt} \cdot |E| \cdot |V| \log |V|\big)$ в худшем случае (алгоритм Йена на базе Дейкстры); шаг 3.4 для каждого пути — $O(|E_b| \cdot (|E|+|V|)\log|V|)$.

## Алгоритм 4. Многокритериальная оптимизация по параметру $L$

**Вход:** граф среды $G$, грузы $C$, коалиции $\mathcal{U}$, сетка значений $\mathcal{L} = \{L_1, \dots, L_m\}$.
**Выход:** Парето-фронт $\mathcal{F}$, компромиссная точка $L^*$.

Критерии $f_1(x) = W_d^{total}$ и $f_2(x) = W_b^{total}$ конкурирующие: уменьшение стоимости строителей (малое $L$ запрещает длинные мосты) увеличивает объездной путь доставчика, и наоборот.

$$
\min_{x \in X} \big(f_1(x), f_2(x)\big), \qquad X = \{\text{допустимые расписания } T \text{ при фиксированном } L\}
$$

### 4.1. Построение кривых стоимости

```
Algorithm 4.1  BUILD-COST-CURVES(G, C, 𝒰, ℒ)
Input:  граф G, грузы C, коалиции 𝒰, сетка ℒ
Output: множество точек {(L, W_d^total(L), W_b^total(L))}

1:  Points ← ∅
2:  for each L ∈ ℒ do
3:      (T, W_d, W_b, ok) ← SCHEDULE(G, C, 𝒰, L)             ▷ Алгоритм 2
4:      if ok then
5:          Points ← Points ∪ {(L, W_d, W_b)}
6:      end if
7:  end for
8:  return Points
```

### 4.2. Выделение Парето-фронта

```
Algorithm 4.2  PARETO-FRONT(Points)
Input:  множество точек Points = {(L, W_d, W_b)}
Output: недоминируемое подмножество ℱ ⊆ Points

1:  ℱ ← ∅
2:  for each p ∈ Points do
3:      dominated ← FALSE
4:      for each q ∈ Points, q ≠ p do
5:          if W_d(q) ≤ W_d(p) and W_b(q) ≤ W_b(p) and (W_d(q) < W_d(p) or W_b(q) < W_b(p)) then
6:              dominated ← TRUE;  break
7:          end if
8:      end for
9:      if not dominated then ℱ ← ℱ ∪ {p}
10:     end if
11: end for
12: return ℱ, sorted by L
```

**Сложность:** $O(|Points|^2)$ — попарное сравнение.

### 4.3. Проверка вогнутости фронта

При минимизации двух критериев геометрически корректный Парето-фронт **вогнут** к началу координат (в отличие от классической кривой производственных возможностей при максимизации, где фронт выпуклый наружу). Критерий: модуль наклона между соседними точками не должен возрастать вдоль фронта.

```
Algorithm 4.3  IS-CONCAVE(ℱ)
Input:  Парето-фронт ℱ, отсортированный по W_d
Output: булево значение

1:  if |ℱ| < 3 then return TRUE
2:  Slopes ← []
3:  for i ← 1 to |ℱ|-1 do
4:      Δd ← W_d(ℱ_{i+1}) - W_d(ℱ_i);  Δb ← W_b(ℱ_{i+1}) - W_b(ℱ_i)
5:      if Δd ≠ 0 then Slopes.append(|Δb / Δd|)
6:  end for
7:  return ∀ i: Slopes[i] ≥ Slopes[i+1] - ε
```

### 4.4. Выбор компромиссной точки

Метод идеальной точки в координатах, нормированных **по диапазону** $\frac{x - x_{\min}}{x_{\max}-x_{\min}}$ (а не по минимуму) — нормировка по диапазону устраняет искажение при сильно различающихся масштабах изменения осей:

```
Algorithm 4.4  CHOOSE-COMPROMISE(ℱ, method)
Input:  Парето-фронт ℱ, метод ("euclidean" | "chebyshev" | "weighted_sum")
Output: точка L* ∈ ℱ

1:  d_min, d_max ← min/max W_d по ℱ;  b_min, b_max ← min/max W_b по ℱ
2:  for each p ∈ ℱ do
3:      â(p) ← (W_d(p) - d_min) / (d_max - d_min)
4:      b̂(p) ← (W_b(p) - b_min) / (b_max - b_min)
5:      switch method:
6:          case "euclidean":    score(p) ← √(â(p)² + b̂(p)²)
7:          case "chebyshev":    score(p) ← max(â(p), b̂(p))
8:          case "weighted_sum": score(p) ← w·â(p) + (1-w)·b̂(p)
9:  end for
10: return arg min_{p ∈ ℱ} score(p)
```

**Сложность Алгоритма 4:** $O(|\mathcal{L}| \cdot C_{\text{Алг.2}} + |\mathcal{L}|^2)$ — построение кривых доминирует над выделением фронта.

## Вспомогательная эвристика A. «Самый дешёвый мост» (greedy по стоимости строительства)

Альтернатива Алгоритму 3, минимизирующая **только** стоимость строительства, без учёта стоимости проезда при выборе пути — вес ребра $\hat w(e) = w_{build}(e)$ (для $E_{blocked}$) или $0$ (для $E_{free}$), вместо $\hat w(e) = w_{build}(e) + w_E(e)$.

```
Algorithm A  FIND-ROUTE-CHEAPEST-BRIDGE(G, c_i, U_i, L)
Input:  граф G, груз c_i, коалиция U_i, ограничение L
Output: (P*, E_b, W_d, W_b)

1:  G' ← (V, ∅)
2:  for each e = (u,v) ∈ E do
3:      if kind(e) = impossible then continue
4:      if kind(e) = blocked then
5:          if ℓ(e) > L then continue
6:          ŵ(e) ← w_{build}(e)                  ▷ ТОЛЬКО стройка, без проезда
7:      else
8:          ŵ(e) ← 0                              ▷ свободный проезд не штрафуется
9:      add e to G' with weight ŵ(e)
10: end for
11: if not HasPath(G', v_s^i, v_f^i) then return ⊥
12: P* ← Dijkstra(G', v_s^i, v_f^i)
13: (W_d, W_b, E_b) ← EVALUATE-PATH(G', P*, U_i)     ▷ Алгоритм 3.4, постфактум
14: return (P*, E_b, W_d, W_b)
```

**Свойство (установлено эмпирически):** при супралинейной (например, квадратичной) зависимости $w_{build}$ от длины ребра решение зависит от $L$ только через порог достижимости — после открытия минимально необходимого моста маршрут не меняется при дальнейшем росте $L$, поскольку любой более длинный мост гарантированно дороже по $w_{build}$ независимо от выигрыша в $W_d$. Это вырождает Парето-фронт по $L$ в одну точку.

## Вспомогательная эвристика B. Приоритет по нормированной стоимости выполнения

В отличие от Алгоритма 1 (приоритет по геометрическому расстоянию, не требующий решения подзадачи маршрута), эта группа эвристик строит приоритет через стоимость выполнения $W_T^i = W_d^i + W_b^i$, полученную Алгоритмом 3 (или эвристикой A) от **начальной** позиции назначенной коалиции:

$$
p_{\text{direct}}(c_i) = W_T^i, \qquad
p_{\text{inverse}}(c_i) = \dfrac{1}{W_T^i}, \qquad
p_{\text{norm}}(c_i) = \dfrac{W_T^i}{\sum_j W_T^j}
$$

```
Algorithm B  ESTIMATE-AND-PRIORITIZE(G, C, 𝒰, L, mode)
Input:  граф G, грузы C, коалиции 𝒰, ограничение L, mode ∈ {direct, inverse, normalized}
Output: приоритет p: C → ℝ

1:  for each c_i ∈ C do
2:      U_i ← assigned_pair(c_i)
3:      (_, _, W_d^i, W_b^i) ← FIND-ROUTE-CHEAPEST-BRIDGE(G, c_i, U_i, L)    ▷ от начальной позиции
4:      W_T^i ← W_d^i + W_b^i
5:  end for
6:  Σ ← Σ_i W_T^i
7:  for each c_i ∈ C do
8:      switch mode:
9:          case direct:     p(c_i) ← W_T^i
10:         case inverse:    p(c_i) ← 1 / W_T^i
11:         case normalized: p(c_i) ← W_T^i / Σ
12: end for
13: return p
```

**Замечание (доказано эмпирически и аналитически).** Поскольку нормировка на $\Sigma = \sum_j W_T^j$ есть умножение всех значений на одну и ту же положительную константу, порядок сортировки по $p_{\text{direct}}$ и $p_{\text{norm}}$ совпадает — оба варианта порождают идентичное расписание (Алгоритм 2) и идентичные итоговые суммы $W_d^{total}, W_b^{total}$.

**Эмпирический результат.** При последовательном выполнении грузов в порядке убывания приоритета расхождение между предсказанной (от начальной позиции) и реальной (с учётом фактического смещения коалиции) суммарной стоимостью растёт с числом грузов для $p_{\text{direct}}/p_{\text{norm}}$ (систематическое накопление, поскольку «дорогие», обычно дальние, задачи выполняются первыми и сильнее смещают коалицию), но остаётся близким к нулю и не накапливается для $p_{\text{inverse}}$ (сначала выполняются «дешёвые», обычно близкие задачи, коалиция смещается на малые расстояния).
